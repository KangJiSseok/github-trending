# GIT-1 Design

## Source of truth

- Linear issue `GIT-1`: bootstrap workspace, web shell, and shared config
- Linear project docs: `PRD - GitHub Trend Radar KR`, `Implementation Plan - GitHub Trend Radar KR`

## Goal

Create the smallest usable monorepo foundation that lets development start immediately without pulling later concerns into the first issue.

## Chosen approach

Use a minimal `pnpm` workspace with three packages:

- `apps/web`: the only runnable app in GIT-1, implemented as a small Next.js App Router shell
- `apps/worker`: manifest-only placeholder so later worker issues can attach to an existing workspace package
- `packages/config`: shared TypeScript package exporting Zod-backed domain constants and schemas

## Why this cut

This matches the exact verification surface requested by `GIT-1`:

- `pnpm install`
- `pnpm --filter web test -- homepage.test.tsx`
- `pnpm --filter @repo/config test`

It also avoids pulling in later issue scope too early, especially DB, Prisma, scheduler/runtime code, CI, and browser E2E.

## Domain contract for `@repo/config`

GIT-1 only defines the shared values explicitly called out in Linear:

- trend windows: `daily`, `weekly`
- timezone: `Asia/Seoul`
- supported GitHub event types used by the MVP:
  - `WatchEvent`
  - `ForkEvent`
  - `IssuesEvent`
  - `PullRequestEvent`
  - `PullRequestReviewCommentEvent`
  - `PushEvent`
  - `CreateEvent`

Anything beyond that, such as freshness thresholds, env parsing, scoring constants, or summary generation settings, is deferred.

## Web shell contract

The homepage is a placeholder shell, not a real data-driven product page yet. It should:

- identify the product as GitHub Trend Radar KR
- mention KST / `Asia/Seoul`
- show placeholder sections for daily briefing, weekly report, repository trends, and methodology
- stay synchronous and presentation-only so unit tests remain simple

The homepage test should verify each of those placeholder surfaces directly so the shell contract is executable, not implied.

## Testing strategy

- Use a red/green `pnpm install` loop for workspace bootstrap
- Add a focused homepage rendering test in `apps/web/tests/homepage.test.tsx`
- Add focused schema validation tests in `packages/config/src/trends.test.ts`
- Defer Playwright and broader integration coverage to later issues

## Explicit deferrals

The following are intentionally out of scope for GIT-1:

- Prisma and PostgreSQL
- `packages/db`
- worker source files and scheduling runtime
- `.env` handling
- Playwright
- CI workflows
- Tailwind or broader design system setup
- API routes and real data fetching

## Risks to watch

- `pnpm --filter` commands depend on exact package names (`web`, `worker`, `@repo/config`)
- Next.js homepage tests are easiest while the page stays synchronous
- shared package imports should use the real workspace package name, not temporary TS path aliases
- root recursive scripts should use `--if-present` so a manifest-only `worker` package does not break `build`, `test`, or `lint`
